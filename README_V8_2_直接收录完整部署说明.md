# V8.2：政策直接收录与真实抓取适配（完整项目）

这是 **完整 GitHub 项目**，不是增量补丁。解压后将 `wind-policy-monitor-V8.2` 文件夹内部的全部文件复制到新仓库根目录（包括隐藏目录 `.github`），通过 GitHub Desktop 提交并推送。

## 本次实现的行为

1. **国内政策不再经过候选审批阶段。** 一条条目在官方公开目录具备可信政策标题、真实发布日期、可访问格式的来源链接、风电或相关新能源政策相关性时，当场生成政策记录并进入 `site/data/policies.json`；`build_site_data.py` 随后将符合要求的记录送入网站查询/展示数据。
2. **正文下载和18个业务分析维度不再是国内入库前置条件。** 正文成功时自动升级同一URL的原有记录；正文失败时保留已发现的标题、发布日期和来源链接，并在同一条记录上标明“正文待补充”，进入详情重试队列。
3. **可信媒体报道可以展示，但不冒充正式法规原文。** 北极星风电政策目录发现的相关政策报道纳入展示；如果尚未取得官方文件，就明确归类为媒体报道。
4. **国家发改委由原动态文件库改为4个官方政策发布栏目：**“通知”“规范性文件”“发展改革委令”“规划文本”，程序分别读取并合并，不在读取第一个栏目后退出。其他国内专站延续V7.1—V8.1的适配与官方备用抓取配置。
5. **国内已取消强制时间覆盖审计。** 日期/分页读取问题仍记录用于抓取质量检查，但不再阻止已取得的政策入库或正文补查。国外保持原有逻辑与21个适配器。
6. **去重及防降级。** 同一政策链接只有一个记录；已经取得的正文不会被下次仅列表成功的结果覆盖。

## 特别注意：本压缩包内的 `site/data/` 是打包时的历史快照

- 新建空仓库：直接使用全部项目文件即可。
- 更新现有运行中的仓库：先备份并保留GitHub仓库最新的 `site/data/`，不要让压缩包的旧历史快照覆盖新的已采集政策和抓取状态。
- 不要删除 `.git` 文件夹，也不要把顶层目录再套一层上传。
- 打开 `Settings > Pages` 选择 `GitHub Actions`，然后从 Actions 运行项目自带的更新工作流。首次建议选择 `provincial`，先看国内抓取效果。

## 如何验收（必须看抓取结果，不只看工作流绿色）

运行完成后检查：
- `site/data/policies.json`：新增加的真实、可追溯政策条目及正文补充状态。
- `site/data/policies_display.json`：网站实际展示条目。
- `site/data/policy_display_decisions.csv`：每条记录被展示/过滤的具体原因。
- `site/data/policy_site_acceptance.csv` 和 `diagnostics/network35_runtime_report.csv`：逐站HTTP失败、官方备用来源与目录识别情况。
