# 风电法规网站 GitHub Actions 依赖安装失败修复报告
日期：2026-10-23

## 1. 这次 Actions 失败的准确原因

在 `logs_108115293624.zip` 中，`update` job 于 `Install dependencies` 阶段失败。
`requirements.txt` 中的 `argostranslate` 会间接引入 `stanza`、`torch`，
并进一步下载 NVIDIA/CUDA/Triton GPU 组件。日志显示下载
`triton-3.8.0`（247.9 MB）到 213.9 MB 时中断，重试六次后出现：
`error: incomplete-download`，使 pip 返回 exit code 1。

诊断步骤中出现 `ModuleNotFoundError: No module named 'bs4'`，
是前面的 pip 整体安装未完成造成的连锁错误。

**这轮没有进入正式政策抓取；诊断脚本显示的是仓库已保存的历史记录。**

## 2. 本次修改

- `requirements.txt`：仅包含抓取、页面解析、构建所必需的核心依赖，
  不再强制安装 `argostranslate` 及 GPU 计算库。
- `requirements-translation.txt`（新增）：独立列出 Argos 离线翻译库。
- `.github/workflows/update.yml`：
  1. 增加核心依赖 pip 下载重试及关键包导入检查。
  2. 先安装必需依赖并运行 Python、Node.js 测试。
  3. Chromium 安装遇到临时 CDN 错误时最多重试三次。
  4. 将离线翻译改为可失败的独立步骤，先从 PyTorch 官方 CPU
     仓库安装 `torch==2.13.0`，避免下载 GPU 的 CUDA/Triton 组件。
  5. 若离线翻译安装失败，该次新闻更新自动禁用标题翻译，继续执行
     新闻抓取、网站数据构建与部署；已保存的中文翻译不会因此被清空。
- `tests/test_policy_workflow_dependencies.py`（新增）：
  防止今后把 GPU 或 Argos 再次加入核心依赖，并检查上述非阻塞策略。

## 4. 如何替换

推荐备份当前 main 分支后，把完整 ZIP 解压，将
`wind-policy-v7-main/` 文件夹**内部全部内容**上传仓库根目录，
注意保留 `.github/workflows/update.yml`。不要直接上传 ZIP 本身，也
不要在仓库里额外套一层 `wind-policy-v7-main` 文件夹。

如果 GitHub 上的 `site/data/` 已有较新的抓取记录，请优先只上传
四文件补丁 ZIP，避免完整包覆盖较新的历史数据。

提交后进入 GitHub → Actions，选择工作流手动运行 `provincial`。
先看 `Install dependencies` 是否通过，再确认离线测试、
抓取、`Verify crawl produced fresh state`、保存和部署步骤。
如果 `Install optional CPU-only offline translation` 报警告，
不会再作为整个工作流失败的依据；该轮新增外文标题可能没有中文译文。
